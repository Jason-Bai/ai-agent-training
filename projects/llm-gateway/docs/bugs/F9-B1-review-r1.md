**原问题复核**

相同模型、完整 Usage 10/1/11、缓存命中 7/未命中 3、`finish_reason="tool_calls"` 时，两种入口现均先保存终态用量的 UTC 观测时间，再拒绝工具正文。

普通路径由 `ProviderCallError` 携带证据；流式路径由失败事件携带证据。两条执行链均将其写入 Attempt。`billing.settle` 继续要求模型匹配、有效完整用量、终态观测时间及足够计价证据，满足后才结算。

新增用例核对到两种入口均：

- 返回 `provider_invalid_response`，流式不产生 `response.completed`；
- 仅调用主供应商一次，不调用备用；
- `usage_complete=true`，状态为 `settled`；
- Agent 扣款与供应商成本均为 0.000280 元；
- 当前预留为零，可用余额为 0.999720 元，总览未知尝试数为零。

该金额也与独立手算一致：`(7×20 + 3×30 + 1×50) / 1,000,000 = 0.000280`。
