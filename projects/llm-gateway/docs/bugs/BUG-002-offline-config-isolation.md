## 现象、影响与已有契约

F3 验收后，用户将 config/gateway.yaml 切换为真实 Provider。源码核对发现：

- tests/unit/test_f3_config.py 的 test_default_registry_is_explicit_mock_without_credentials 直接 load_registry()，断言当前运行配置全部为 Mock。
- tests/smoke/conftest.py 将项目 config 复制到临时运行目录，同时排除 credentials.yaml；真实 Provider 配置因此进入不应访问真实凭据的离线进程。
- tests/conftest.py 的 app fixture 只注入 MockProvider，仍由应用读取默认模型注册表；其他使用默认装配的测试也需核对。

以上为静态定位，不冒充已运行失败复现。运行配置内容不应决定离线测试是否通过；离线测试不得读取实际凭据或连接外部 Provider。ENV 与 Provider 独立，不引入 .env.test。

本问题关联待讨论落文的 F3-O1，先恢复可靠测试基线，再开展应用组装和计数策略重构。原 F3 验收记录保留历史结果。

## 修复范围

测试自行创建确定的 Mock 注册表或临时 gateway.yaml；配置加载测试仍执行真实 YAML 解析，进程冒烟仍从临时文件启动真实单 worker 服务。测试独立管理所需 .env 和假配置，不复制维护者的运行配置、实际 .env 或真实凭据。

保持生产加载路径、配置优先级、计数资源校验、Provider 协议及 HTTP 契约不变。不将待测解析器、应用装配或真实 HTTP 边界替换成永远成功的 Mock。真实组保留 --run-live 的显式启用边界。
