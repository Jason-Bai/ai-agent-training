**二、独立反例与故障时序核对**

1. **旧POST仍阻塞或发送失败，GET已启动甚至完成。**  
   创建Trace与生成Trace为不同对象；`defer`避免旧创建记录覆盖生成恢复项，`flush_pending`对已存在的有效流式记录只核对状态。已提交pending不会因创建响应传输失败被写成生成失败。对应发送屏障、headers/body故障测试保留了独立SQL状态和零调用断言。

2. **上次claim回滚留下orphan，下一次claim已提交但尚未注册任务，恢复线程同时到达。**  
   当前`reconcile`与`subscribe`共用请求级锁；注册成功后清除orphan。因此恢复不能穿过认领到注册的窗口提前写failed。新增恢复测试确实阻塞在提交后窗口，断言恢复等待，并最终核对唯一Provider调用；不是用恒定成功替身绕过Store。

3. **生成已停止、终态提交待恢复，新GET到达。**  
   `awaiting_persistence`将原执行者的待提交收口与无所有者running区分。订阅不会抢先调用通用中断恢复。新增真实PG测试检查了终态延后窗口，并最终断言Usage为10/3/13、Provider原错误分类保留、唯一失败事件和一次调用。

4. **增量或completed已经提交，但提交确认丢失。**  
   已存事件通过PG查询读取；生成不重试Provider、不重复追加delta。`finish`锁定请求并尊重已有终态，completed不会被后续恢复改为failed。故障测试在真实commit/rollback后丢确认，独立连接核对连续seq、唯一终态和实际调用次数。

5. **分页读取请求行后，生成又提交新事件。**  
   `read_events`将本页事件上界限制为已观察到的`last_event_seq`。后续提交留给下一次查询，避免请求状态与事件页来自不一致的观察边界。205条历史增量加终态的PG回放覆盖多个页边界；Store测试同时检查连接已释放。

6. **慢订阅卡在发送，而生成、快订阅及另一请求继续。**  
   生成没有等待订阅发送；每个订阅单独持有游标、页和计时状态。实际ASGI发送测试覆盖headers、delta、heartbeat、terminal、最终空帧的阻塞及OSError。其断言检查生成终态、Attempt和调用数，而非仅检查HTTP返回。

7. **两个活跃订阅首段实际发送交错；完成后或重启后回放。**  
   TTFT回调在实际send成功后触发，生成Trace只接受第一次观测。终态历史订阅不附着生成回调。指标测试安排慢发送先进入、快发送先完成，并核对内存观测与PG诊断；历史及重启回放不改原指标。

8. **读库、断连及生成期限相互叠加。**  
   订阅错误只结束本订阅，不发布模型失败、不关闭共享Provider。B期限从首次认领前开始并传入认领、Attempt及事件事务，重连不重置；订阅则采用独立心跳和单send期限。实际TCP/PG测试证明断连后继续提交及携游标续传，不能仅靠ASGI完整响应证明该行为。
