## 2. 固定准备与共同断言

- 测试统一使用订单A123、充电器故障，复用basic_text、结构化售后Schema及原公共成功/续传/取消数据。Mock返回确定文本或合法JSON、typed流增量与合成Usage；真实保留实际文本/Usage，按相同事实与契约验收。
- 小限额测试配置按场景选择global=2/agent=1等组合；普通非治理回归显式使用充足且有限的配置。原F10的20并发实验配置global>=20、per-agent>=20，原负载及600秒持续时长保持。
- Agent A/B使用测试CLI真实签发；A的两个有效凭据仍归同一个agent_id。两条Provider和逻辑模型按现有定义接入，更换模型、协议或凭据不能绕过全局/Agent限制。
- 屏障标明已获取名额、已进入Provider、已收到首个文本、已停止读取、正在关闭、关闭完成等观察点。用事件控制顺序，不能只靠sleep猜测并发。响应和副作用按request_id关联，不按返回列表位置拼接。
- HTTP错误检查四字段、状态码、request_id及脱敏；SSE检查seq、唯一终态、断点后的完整事件、心跳/EOF不算成功。拒绝必须查新增Provider调用、Attempt、预留和费用，不只断言429。
- 最终释放后检查全局/各Agent计数为0，生成/订阅/清理/取消任务收口；占用尚未归零时必须能对应仍活跃的本地任务。内部快照仅由测试进程观测，不增加产品调试路由。
