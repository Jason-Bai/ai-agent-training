### F12-R1-02 — 文本渲染阶段及诊断：已关闭

合法共享文本仍提前缓存并保留已确认指纹；仅捕获 `prompt_too_long`，不吞其他输入错误或异常。缓存不可用时，等实际筛选到 render 阶段才正式排除候选。

因此：

- 全部停用先返回 `no_available_endpoint`。
- 能力或输出阶段耗尽不会被渲染超限抢先覆盖。
- 到达渲染阶段后，超限候选记录 `prompt_too_long`，无初选，`error_stage=routing`。
- 成功渲染的早期指纹仍保留；超限输入不会被伪造出完整消息指纹或 Token 数。

普通和流式创建入口的四个 HTTP/PG 节点验证了阶段、候选原因、响应信封、请求 ID、正文不落库及零调用/Attempt/事件/费用。修复没有复制渲染或路由算法作为测试黄金。原缺陷关闭。
