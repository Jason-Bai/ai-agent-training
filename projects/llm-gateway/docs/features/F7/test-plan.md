## 1. 范围与通过标准

证明一次请求在固定总期限、共享尝试额度和原始授权内恢复；每次实际调用及其结果有证据；流式内容提交或取消接受后不再恢复；Request只有一个最终结果。覆盖普通文本、普通Structured Output及首条非空delta提交前的Streaming。

本项共**52组必测场景**：入口A5、配置K4、恢复R6、时间T6、格式J6、增长G4、流式S6、取消竞争C5、持久化P6、适配及回归V4。每组参数化分支全部执行，组数不等于pytest节点数；收集后建立组到实际节点映射。

| 层次 | 证明范围 | 不能单独证明 |
| --- | --- | --- |
| 单元及脚本MockProvider | 决策、次数、消息、计数、退避和时间计算 | 数据库提交、真实协议或网络送达 |
| 真实PostgreSQL | 跨连接状态、Attempt、事件、提交不确定性、迁移 | 远端接收调用/实际收费 |

| 本地HTTP协议服务 | 两条实际适配器及SDK的参数、异常、流和隐式调用次数 | 真实供应商稳定性、价格或容量 |
| 独立TCP客户端/子进程 | 心跳实时到达、断连续传、关停/崩溃恢复 | 多实例协调、远端计算停止 |

### 1.1 共同断言与固定数据

- 使用订单A123、问题“商品破损，请分析”；固定模板/变量/原文。结构化示例Schema为对象，必填order_id字符串、action枚举draft_ticket/ask_order，additionalProperties=false；业务事实正确性不冒充Schema保证。
- 普通HTTP JSON恰为success/code/data/message；成功data保留text/usage，结构化另有parsed，失败不含可用parsed；普通ID只在X-Request-ID。创建、订阅、取消保留F5-O2/F6协议，不新增公开attempts、actual_model、协议、retrying事件或Request状态。
- 所有适用场景同时断言Provider真实进入次数、顺序、模型/请求ID、准确消息和参数。登记Attempt与已进入Provider分开，跳过候选/入口拒绝零调用；不把数据库行数直接当供应商接受/计费次数。
- 独立PG连接检查Request/Attempt关联、尝试原因、输入快照/指纹、计数与预算、结果/Usage。中间Attempt失败不提前终结Request；最终completed/failed/canceled互斥。流式seq连续、无重复、终态事件唯一，恢复不删除历史。
- 使用已知Usage(3/2/5)、(4/1/5)、(2/2/4)，全已知三次汇总为(9/5/14)；任一次未知整体null，同时保留内部已知部分。未取得Usage不能补零，不推断费用。
- 响应、日志、公开SSE和诊断错误不含测试假Key、数据库密码、原始异常或Python堆栈。按已授权规则，PG有效输入快照及修复输入可含正文；不以课程“Trace不含完整敏感Prompt”错误禁止本项目明确授权的输入存储。公开面与受控证据分别检查，禁止真实凭据落库/归档。
