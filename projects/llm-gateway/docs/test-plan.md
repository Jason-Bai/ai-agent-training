## 已确认的共用验收原则（2026-11-03）

用户已确认：公共功能用例共用，在Mock与真实Provider下分别执行；特殊故障仍允许用Mock/受控上游稳定制造。该原则不等于每条单元测试都要调用真实模型，也不以两套独立业务断言代替共同验收标准。

| 场景 | 执行及断言原则 |
| --- | --- |
| 普通、结构化、流式、续传、取消 | 共用场景步骤、输入业务事实和Gateway行为断言，分别接Mock与真实Provider。确定性Mock数据与真实输出按同一业务要求验证，不逐字固定真实回答或Token数。 |
| 超时、429、畸形帧、指定时刻断流、事务/取消竞争 | 使用可控替身确定性验证；真实环境实际出现时仍按同一错误契约检查，不要求远端按测试脚本制造故障。 |
| 模板、配置解析、数值精度等纯逻辑 | 不依赖远端，独立测试，不为重复执行而增加真实调用。 |
| 真实协议、回答质量、实际Usage及延迟 | 用真实Provider取得证据；Mock只验证模拟输入下的处理。Mock Usage是模拟数据，真实Usage是实报，未知仍未知，不能要求两个Provider返回相同计数或费用。 |

ENV、Provider、测试执行范围分别管理。ENV可以作为被测条件覆盖配置加载/环境相关行为，不能自动将Provider绑定成Mock或真实，也不因ENV值静默跳过关键主链。真实接入可以在ENV=test中进行，不等同于production部署。当前应用ENV行为不在本次原则确认中改变。

执行顺序为开发时先运行Mock公共功能和受控故障用例，再显式用真实Provider执行公共功能，最终完整回归汇总全部证据；两类结果分别留证，不互相代替。真实访问仍需--run-live显式启用。共用验收原则已确认，具体测试重构范围、用例映射与实现须在当前事项的测试方案中确认；原Feature工件不追溯改写。

当前已确认在[BUG-002](bugs/BUG-002-offline-config-isolation.md)补齐配置隔离及上述五类公共功能的最小共用验收层，按TDD实施，不整体重写历史单元/协议/故障测试。

## 测试层次

| 层次 | 验证对象 | 证据边界 |
| --- | --- | --- |
| 纯逻辑单元测试 | 契约、模板、模型能力、校验、恢复决策 | 不证明 FastAPI 或真实供应商可用 |
| MockProvider 服务测试 | 传入消息、调用顺序/次数、故障恢复、取消、Trace | 不证明外部 API、密钥和网络行为 |
| FastAPI 本地接口测试 | HTTP 错误出口、注入、SSE 增量与终态 | 不证明真实供应商增量和 Usage |
| 真实 PostgreSQL 及进程恢复 | 跨连接提交、回滚、关联、序号、未知提交核对、崩溃恢复与资源隔离 | Mock/SQLite 不替代这些证明；不证明多实例协调 |
| 适配器协议测试 | 两种接入的请求转换、事件和异常归一化 | 可用替身传输，不等同真实服务 |
| 显式真实 Provider 冒烟 | 模型名、密钥、结构化/流式能力、真实返回 | 只证明该环境与该次调用，不等同生产可靠性 |

上述层次描述观测与证据边界，不要求公共功能在各层复制成不同业务用例。公共步骤与断言共用，Provider专属留证在各自夹具/观察器中完成。

MockProvider 应能按脚本返回文本、结构化候选、增量、Usage、正常完成，或抛出连接超时、限流、认证异常、流中断；并记录每次调用的模型、消息、参数和取消/关闭次数。默认测试不发真实外部请求，不加载真实密钥。

## 最终验收执行口径（2026-11-02用户明确要求）

开发中的目标测试可以按影响范围选择执行；最终验收必须针对最终代码完整执行现有用例，并显式启用已配置真实Provider：`uv run --python 3.12 python -W error -m pytest --run-live -q`。不得以付费为由跳过live，也不得用旧版本结果替代本轮未重跑节点。当前用户已授权本次完整真实调用；凭据仅供测试加载，不在聊天、日志或证据中展示。

只有本轮全部用例实际执行并通过，且代码审查满足工作流，才可称验收通过。网络、凭据、额度或其他原因导致未执行/失败时如实记录待验收，不跳过或放宽断言。已执行的历史回执与审查报告保留原样，最新验收记录注明完整命令、版本、结果和真实调用范围。

## 执行节奏与并行边界

设计和测试方案仍分别确认；开发中先跑目标测试和相关回归，稳定集成后执行本项必要全量。相关代码、契约或证据变化、测试失败及未解决问题触发相应复测，已确认的关键边界和副作用验证不得省略。

已确认且前置接口稳定、文件和资源可隔离的任务可并行开发，由统一集成者处理公共接线和迁移，按README顺序交付。数据库停启、宿主端口等故障套件串行运行；不同测试库不等于宿主资源完全独立。真实调用仍按已确认范围显式执行。

提交前一次自检，随后按当前工作流由全新上下文独立Agent完成三维独审，Claude Code为可选工具，完整审查最多三轮。后续轮次复用可核实未变基线并复核新差分/影响链；没有阻断项和关键证据缺口即结束，不重复开展同目的评估。具体约定见[工作流](../AGENTS.md)。
