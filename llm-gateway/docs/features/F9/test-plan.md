# F9 用量与计费测试方案

[整体设计](design.md)已于 2026-11-03 确认。本测试方案已由用户单独确认，以下均为预期结果。

| 场景 | 可观察的通过标准 |
|---|---|
| 凭据、归属与迁移 | 401 无模型调用；跨 Agent 查询/订阅/取消返回 404 且不启动流。换钥匙后新钥匙仍可读原请求；旧记录不串户，不向新 Agent 补扣。 |
| 拨款与并发 | 重放同一笔拨款只入账一次。两次并发预留单笔均够但合计不够时，只允许一次真实上游调用。 |
| 计价与估算偏差 | 用确定价格、缓存分类和输出上限手算金额；覆盖命中、未命中、价格版本更换与时段边界。实际费用超过预留可为负，下一次付费尝试被拒，拨款后恢复。 |
| A123 混合尝试 | 主调用未知、备用成功，检查供应商调用两次。用设计示例核对余额 0.984、列表一行、详情两笔、未知用量一次；恢复预算不足时备用调用为零次。 |
| 流式与取消 | pending 创建未预留，首次订阅触发一次；多订阅、断连、续传及重复读终态不增账。分别测试调用前取消和进入上游后取消，按正向证据释放、结算或待核实。 |
| 重启和人工处置 | 分别在预留后、调用后及结算提交确认时制造中断。验证恢复后不会重复副作用；人工核费、确认零费用和平台承担均可追溯，重复/竞争处置不能二次扣款。 |
| 汇总和查询 | 用多个 Agent、相同创建时间、多个请求及跨时间边界验证稳定分页、总额不受分页影响。真实已知、未知、Mock、无记录分别验算；待核实金额不二次扣减。 |
| 对账 | 一笔有 Attempt 级证据，一笔只有供应商账户期间总额。核对逐笔处置与期间差异，重复导入相同凭证不重复调整。 |
| 基线和接入 | 默认 Mock 10/1/11、费用零。真实模型探测归属调用方，/healthz 零费用。覆盖 DeepSeek Chat 与 Responses 的缓存字段、缺失终态 Usage 和结构化调用，原有流与错误契约回归。 |

开发阶段先对上述行为记录目标 Red，使用可控 Provider 回报、固定价格和隔离 PostgreSQL，分别核对响应、Attempt、账务及调用计数。端到端使用真实 HTTP 进程和测试库，宿主数据库故障场景串行。最终在 Python 3.12 不加筛选运行 pytest --run-live，全量通过且无跳过或筛除，并按项目工作流进行独立审查。实付账单核对的证据单列，测试账单样本不能替代真实供应商账单。

## 可复算的基准与边界用例

下表金额以元计，指定的测试价格和时间均为受控样本。使用真实适配器接本地协议替身驱动付费路径。默认 Mock 始终按零费用处理。每笔操作同时读取 HTTP 结果、数据库账本、Attempt 与上游调用计数，以独立的期望数值核对。

| 编号 | 输入或故障点 | 可直接验收的结果 |
|---|---|---|
| B01 正常结算 | 拨入 1；每百万 Token 单价分别为命中 0.4、未命中 2、输出 8；本地输入估算 250，输出上限 100。实报输入 200（命中 150）、输出 20 | 预留 0.001300，费用 0.000320，可用余额 0.999680。按两种协议返回等价数据，结算一致；修改价格版本后重复查询旧请求仍为原金额。 |
| B02 负余额与恢复 | 可用 0.010，预留 0.009，实报计价 0.012；再尝试、拨入 1、再次尝试 | 结算后余额 −0.002，下一次付费尝试调用计数零；拨款后余额 0.998，足额请求能启动。 |
| B03 并发与幂等 | 拨入 0.010，两个独立请求分别需要 0.008；阻塞首个上游，待另一个请求返回后再释放 | 仅一次上游调用，仅一笔有效预留；相同拨款操作号重放不改变总额。临界值另测余额恰好足额和略低于预留。 |
| B04 未知与人工处置 | 从 A123 主模型未知、备用已结算 0.006、当前可用 0.984 的同一初始状态分别运行三种处置 | 核实主模型费用 0.008 后可用 0.986；确认零费用或平台承担后可用均为 0.994，后二者的供应商侧证据状态可区分。重放处置一次不会再次改变金额。 |
| B05 计价证据与故障 | 缺少可用预留价格、实报缺失、分类之和不等于输入、缓存价与未命中价不同但缺少拆分、计价时段不确定 | 无法预留时上游零调用。已发起则保留不确定部分待核实，不能把本地估算补为实报。时段边界按固定时钟和两个价格版本核对。 |
| B06 归属与泄漏 | 两个 Agent、同一请求 ID，轮换并撤销旧凭据，进程重启；检索专用凭据标记 | 新钥匙可读取本 Agent 的历史；跨户访问返回 404、无效凭据 401。签发后在业务响应、Trace、日志和数据库中检查无明文密钥，路由不能接受正文冒名。 |
| B07 查询边界 | 准备同时间戳的 101 个请求；测试页长 1、50、100、0、101，损坏游标，from/to 两端恰有记录 | 合法分页遍历与直接数据库排序逐行一致；默认 50，非法参数 422；左闭右开；仅有模糊归属的历史行不能出现在任何 Agent 的结果中。 |
| B08 真实接入与回放 | Chat 和 Responses 各经过普通及流式入口，记录脱敏实报分类、价格版本、金额；流式收到终态后再读事件 | 用响应中的真实分类和配置单价独立复算，比较账务查询及 PostgreSQL；重放前后 Attempt、账务笔数及金额一致。缺失证据只能记未知，不以模拟值替代真实通过记录。 |

## 执行与交付

先用测试专属 PostgreSQL、Agent 和一次性凭据执行目标 Red/Green，再跑真实进程、并发屏障及重启场景。进行原始凭据泄漏检查时仅报告出现位置及计数。真实接入使用本机已有 Provider 配置，测试数据与开发数据库隔离。

最终命令为 `uv run --python 3.12 python -W error -m pytest --run-live -ra -q`。保留实际收集和运行数量、原始回执、独立审查结论及代码改动导读。供应商总账样本的导入与差异核对属于必测逻辑。若未取得可关联的真实账单，应在结论中明确实际账单核对未验证。

## 开发验证记录

身份入口 Red 复现 422 而非 401，总览入口 Red 复现 404 而非 401；价格与缓存分类 Red、账本缺少新表的迁移 Red 已分别留存输出。核对正常价格、两种上游格式、预留与并发、未知费用处置、轮换/重启、跨户保护、总览及分页的结果见[开发回执节选](evidence-development.json)和[账本与迁移回执](evidence-ledger.txt)。B01 核对到 0.001300 预留与 0.000320 费用；A123 的 HTTP、独立 SQL、三种人工处置与重放均通过。旧回放夹具须显式构造已知所有者才可读取；未知所有者继续拒绝。真实供应商出具的账户账单未提供，用测试账单验证了对账与未分配差额。

不筛选的全量初跑 1978 通过、3 失败，涉及两条有主的旧回放夹具与一个手写 TCP 请求。补上测试归属/凭据后定向 6 项通过。修正后的同一源码及测试在 Python 3.12 执行 `uv run --python 3.12 python -W error -m pytest --run-live -o junit_family=xunit1 --junitxml=… -ra -q`，1981 通过，耗时 606.16 秒，0 跳过/筛除。其中真实 16 例，6 例额外记录缓存计数、单位价版本与供应商成本。见[全量原始回执](evidence-all-live-r1.xml)。待首轮独立审查。

## 首轮独审修复

[首轮完整报告](review-r1.md) BLOCKED。已核实并按原问题补充回归。

- P0 归属绕过。两个 %0A URL 由执行者复现。订阅、取消改成实际端点的归属依赖；Trace 与账务按账户限制查询。非法跨户请求 404，状态、账务与上游调用均不变。[初始复现](review-experiments-r1.txt)。
- P1 非终态 Usage。诊断可以记录观察到的计数，付费结算还需要可信终态证据及 billing_observed_at。中间帧含 Usage 后协议失败会保留待核实预留；终态实报后传输损坏仍可结算。
- P2 预留漏算已配置涨价。请求截止前可能生效的价格版本参与最高费率预留。截止之后的版本不多占预算。
- P2 错用入账时间。计价使用适配器观察到终态的 UTC 时间。独立验证“上游切价前完成、入账跨界”和“上游自身跨界”，前者正常结算，后者待核实。[计价原始复现与复测](evidence-r1-pricing-fixes.json)。
- 关键补证。隔离 PostgreSQL、Gateway 子进程与本地真实 HTTP 适配器构造两种 SIGKILL 时序，分别在预留提交后（上游 0 次）、上游进入后（上游 1 次）终止进程。重启及两次回放后均保留一笔 0.008 元未知预留，供应商成本及 Agent 扣费未知，账户余额 9999.992 元，未新增调用或扣费。[进程回执](evidence-paid-restart.txt)。2 项通过。
