# F8 实施步骤

设计与测试方案均已确认。各切片先以 HTTP、持久化或工作流程测试取得预期失败，再实现并运行相同断言。临时证据按切片分开保存。

1. 探测写入。负责 gateway 和中间件的探测分支、请求表约束迁移及数据库版本门禁、探测故障和迁移测试。复用普通调用终态核对。
2. 诊断测量。负责普通和流式尝试的实际 Provider 耗时、退避等待和停止原因，从执行器传递至持久化。与探测切片只按独立函数或局部变更集成。
3. 诊断查询。独立只读查询与 HTTP 模型，一致读取元数据并投影，覆盖 SQL、HTTP、只读性与脱敏。写入和读取接口约定见设计，不新增状态所有者。
4. 集成。核对各切片字段、六态、并发、重启、旧版迁移、双协议真实链路。涉及数据库停启的故障套件仅由集成者串行运行。
5. 记录代码导读和证据，冻结安全差分，全新独立 Agent 三维审查；若修复重新验证。最终代码无筛选执行全量 --run-live，并逐项核对回执。

以上五步已完成，历次测试与独立审查回执见[验收记录](test-plan.md)。
