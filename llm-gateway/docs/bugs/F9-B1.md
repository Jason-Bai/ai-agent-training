# F9-B1 Chat 终态计量判断不一致

2026-11-03，F9 三轮独审后仍有一项 P2。用户听取通俗说明后确认统一普通/流式终态判断，并补成对测试、全量回归及重新验收。此前三个完整报告和证据仍保留于 features/F9，不将其改写为通过。当前作为单独 Bug 修复闭环，第 1 轮独审待执行。

## 现象与设计修正

同一 model/usage/cache 的 tool_calls 结束，普通路径确认费用 0.00028 元，流式路径却认为最终用量及金额未知。两种路径的业务输出均拒绝。根因为两份不同的终态判断。

普通和流式共用 constants.CHAT_TERMINAL_REASONS，先识别可确认最终用量的上游终态，再校验正文。用量已确认且计价证据足够时照实结算，普通和流式响应继续按各自业务协议表达生成失败。

## 已确认测试范围

普通和流式分别覆盖 tool_calls、无终态与未知终态，共六个 wire 集成场景。核对生成拒绝、Provider 调用一次且无备用、usage_complete、已知用量与未知次数、Agent 扣款、供应商成本、预留释放和余额。旧实现应仅流式 tool_calls 失败。修正后同一六例及相邻计价/协议测试通过，再完整开启 --run-live 不筛选回归。按 Bug 路径另启全新审查 Agent，最多三轮。实际供应商账单仍未提供。

## 代码阅读

src/constants.py 定义共享识别集合；src/providers/base.py 与 src/providers/streaming.py 在两个入口应用它。tests/integration/test_f9_tool_terminal.py 对同一份证据构造两种上游格式，通过完整 Gateway 和隔离 PostgreSQL 检验最终账目。其他 F9 能力的导读见 ../features/F9/implementation-summary.md。
