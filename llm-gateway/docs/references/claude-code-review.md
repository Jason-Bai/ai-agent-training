# Claude Code 独立审查：调用与取证

1. **直接调用本机 `claude` CLI**。沿用 Claude Code 既有模型、认证和连接配置；本项目只依赖其审查能力，不硬编码后端模型，不为常规审查调整模型参数或改写全局配置。当前已验证路径不需要 acpx 中转。
2. **使用已验证的进程级兼容参数** `CLAUDE_CODE_INLINE_TOOLS=false`，规避多次读取后的 `tool_definition / tool_reference` 协议错误，保留 Read 能力。它只作用于当前调用；升级 Claude Code 后若考虑移除，先重跑多文件读取并取得最终结论的验证，不能仅凭普通对话成功判断兼容性。

在项目目录准备好审查 prompt 文件后调用，例如：

提示词使用[三维审查模板](../templates/ClaudeCode审查提示词模板.md)，执行前归档到当前事项目录 `review-prompt-r<轮次>.md`。下面命令中的临时输入文件仅为调用示例；实际应读取归档文件或其经摘要核对一致的副本，不只保留可丢失的临时提示词。

```bash
CLAUDE_CODE_INLINE_TOOLS=false claude --print \
  --tools Read --allowedTools Read \
  --strict-mcp-config --mcp-config /tmp/claude-review-mcp-empty.json \
  --no-session-persistence \
  --output-format stream-json --verbose \
  < /tmp/review-prompt.txt > /tmp/claude-review.jsonl
```

上述命令先由执行者创建独立临时 `/tmp/claude-review-mcp-empty.json`，内容为 `{"mcpServers":{}}`。这是当前调用的工具限制，不读取/改写用户全局MCP、模型或认证配置。F5第2轮已验证该组合：初始化实际tools仅Read、mcp_servers为空，全部实际工具调用仅Read且正常结束。仅提供 `--tools Read` 不足以证明没有加载其他MCP；还须核对初始化与实际调用日志，不能仅凭参数声称范围受限。

3. **给出具体审查范围**。Prompt 列明用户需求/确认来源、设计、测试方案、实现导读、变更基线、实际变更、相关源码/测试和原始执行证据；无 Git 时提供可用快照/差分，无法取得的材料注明缺口。分开用户约束、实现者解释和运行证据，允许审查者独立质疑设计与解释。逐项核对需求正确性、实现一致性、系统正确性，并独立推导未被既有测试覆盖的反例/时序。优先逐文件读取，避免巨型 Read 截断；排除 `.venv`、缓存、真实凭据和运行配置，只读清单明确列出的安全配置快照/示例。当前权限仅 Read，不重跑测试；实验需求由执行者运行并回传原始证据。
4. **完整结果才算完成审查**。核对实际读取范围、三维覆盖/独立反例及未验证项、最终报告、进程退出码 0、结果 `is_error=false` 和正常结束（已验证为 `stop_reason=end_turn`）。只有进程启动、几次 Read、流中有活动，或单独的 `subtype=success` 都不充分；`is_error=true`、API 错误、超时、初始化停滞、回合耗尽均不能称为审查通过。完成审查也可能得到 BLOCKED；通过还须无 P0–P2，且无影响验收的关键证据缺口。普通范围外限制单列说明，不自动阻断。
5. **保留可核验记录并评估意见**。源码/测试审查前后做哈希核对；保留每轮实际输入的 `review-prompt-r<轮次>.md`，不覆盖已执行版本。原始结论按需保存到当前 Feature/优化的 `review.md`；多个 Bug 共用目录时，提示词及报告文件均加 Bug 编号前缀。轮次、发现、复现与处置回写对应测试方案或 Bug 记录。不盲从审查建议；区分已复现、静态确定和待验证风险，严重等级按实际影响判断。工具调用故障与正式审查发现分开记录，不通过换会话重置三轮审查计数；旧事项没有留存的提示词不补造。
6. **调用失败先定位，避免反复重启**。从普通对话、单文件 Read、多文件 Read 加最终结论逐步验证，区分权限、输出截断、工具协议与任务处理时间；保留同一运行进程并检查实际输出，不仅延长超时或试换模型。复现后只改变一个调用因素，并用相同场景复测；仍不能完成时报告具体失败阶段，保持“待独立审查”。

上述方式已通过三文件缺陷识别和 F1 真实完整审查验证。定位、单变量对照和验证边界见 [Claude Code 调用修复记录](../bugs/BUG-001-claude-code-inline-tools.md)，实际审查结论见 [F1 原始报告](../features/F1/review.md)。

2026-11-01，用户确认将需求正确性、实现一致性、系统正确性固化为审查框架，并同步工作流和实际提示词归档。该改进源于对 [F4 原审查及其静态验证边界](../features/F4/review.md)的回看：新增三维报告、独立反例及材料来源要求。原调用方式已验证，新增框架的审查效果待后续实际使用验证，不以文档更新宣称缺陷发现能力已经提高。

首次实际使用见 [F4-O1两轮审查与处置](../features/F4/optimizations/O1/test-plan.md#36-原生-claude-code-第1轮与处置)：首轮发现README目录树漏迁移（P2）及状态滞后（P3），补充非链接路径核对后复现、修正、复测，二轮APPROVED。目录迁移不能只验Markdown链接；回传摘要须明确哪些是沿用的原始回执，关键输出应持久归档。该记录只证明本次发现与闭环，不代表普遍检出率提高。

F5的[实际两轮记录](../features/F5/test-plan.md#310-最终验收与第2轮审查处置)补充两点：首轮虽APPROVED，执行者仍复现了元信息遗漏并用实验否定一条零Attempt推导，不能把Approved当作正确性证明；报告自述的读取/复现与实际日志不一致时，以日志和原始回执为准，原文保持不改。首轮一次范围外MCP请求被权限拒绝未执行，第二轮采用上述进程级空配置后仅Read；第二轮全部必读实际覆盖，P3测试缺口补HTTP两例闭环，产品源码保持受审版本，不为非阻断测试补强重开完整审查。该操作经验基于本机Claude Code 2.1.311的实际调用，不是对所有版本的兼容性保证。
